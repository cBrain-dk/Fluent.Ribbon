# cBrain Fluent fork

This fork is based on upstream Fluent.Ribbon v11.0.2
(`ce56b60ca892d1505b7f80826330c676f41fda0a`). Source changes live on the
`fluent-wrapper` branch of https://github.com/cBrain-dk/Fluent.Ribbon.

## Private extensions

`Fluent.IKeyTipServiceHost` allows the keytip service to work with the F2
ItemsControl-based CommandBar. It exposes enabled, focus, collapsed and keytip
state, plus `AsControl()`, `GetKeyTipServiceTarget()`,
`CanSetFocusFromKeyTipService()` and `SetFocusFromKeyTipService()`. `Ribbon`
implements the interface. The interface-based `KeyTipService` constructor
coexists with the upstream `KeyTipService(Ribbon)` overload and retains Fluent's
target and focus behavior.

The protected factories `ComboBox.CreateQuickAccessComboBox()` and
`SplitButton.CreateQuickAccessSplitButton()` allow derived controls to choose
the clone type. They replace only allocation; Fluent's inherited creation
methods still own clone registration, bindings, item transfer, event handlers
and small-size/no-re-add setup.

`Fluent.CBrain.RibbonComboBox` and `Fluent.CBrain.RibbonSplitButton` live in
`Fluent.Ribbon/CBrain/` and compile into `Fluent.dll`. Their factories return
fresh instances of the matching native type, and their public creation methods
mark the inherited clone with `IsElementInQuickAccessToolBar=true`. Further
subclasses override the factory when their clone must retain the derived type.
The `Fluent.CBrain` namespace keeps `Fluent.*` references usable inside
`CBrain.*` consumers without introducing a `CBrain.Fluent` namespace.

These controls remain private fork features. Rebase on stable upstream releases;
retire the host or factory patches only when a released equivalent preserves
the native clone and CommandBar/keytip contracts.

## Package and compatibility

The fork ships one `Fluent.Ribbon` package containing `Fluent.dll` for `net48`
and `net10.0-windows`. It preserves the upstream license and signing, with assembly
identity `Fluent, Version=11.0.0.0, Culture=neutral, PublicKeyToken=3e436e32a8c5546f`.
Both targets depend on ControlzEx 7.0.3; net48 additionally depends on
System.Memory 4.6.3. Theme XAML is generated by the normal build.

Package versions use `<Fluent version>-0.<cBrain revision>`. The project prepares
`11.0.2-0.3`; the published `11.0.2-0.2` remains unchanged. Version properties live
in `Fluent.Ribbon/Fluent.Ribbon.csproj`, with GitVersion overrides disabled.

Consumers must pair the selected package with its matching source revision.
The namespace change requires consumers of the native controls to recompile and
update CLR/XAML references; see the [control README](Fluent.Ribbon/CBrain/README.md#consumer-migration).

## Validation and publication

`CBrain.Fluent.Ribbon.Tests` is the non-packable STA test project. It verifies
native clone type, freshness, quick-access membership, inherited setup and shared
assembly identity. The solution and Nuke Test target include it.
`Build-CBrainWrapper.ps1` builds and tests both targets in source or package mode.

`Publish-CBrainWrapper.ps1` runs source tests, packs Release and publishes through
`rdadm nuget push` to the internal F2U feed. Publication and upstream contributions
require explicit owner authorization. Before publication, validate the exact
artifact and an isolated feed restore, and ensure the version is unused. Published
versions must never be replaced.
